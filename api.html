API reference

A tiny, fast Svelte 5 data grid for fintech UIs — virtual scroll, canvas sparklines, batched realtime updates, sort/filter, selection, grouping, a server-side data source, export, and column pinning.

Install

npm i bo-grid          # peer: svelte@^5
npm i xlsx             # optional, only for exportXLSX()
import { Grid, type ColumnDef, type GridRow } from 'bo-grid';

GridRow interface

The minimal contract every row must satisfy; add your own data fields alongside.

interface GridRow {
  id: number;            // stable identity (used as the render key)
  flashSeq?: number;     // legacy row-driven flash only (flash: true)
  flashDir?: 'up' | 'down';
  [field: string]: unknown;
}
Make hot fields (price, volume…) reactive $state so updates flash and re-render only the changed cell — not the whole table. With flash: 'auto' the grid derives the flash itself — write the new value and nothing else; flashSeq/flashDir are needed only by the legacy flash: true mode.

Conditional formatting

Data bars, icon sets and colour scales paint analytics cues into numeric cells. Data bars auto-range over the current view (or set min/max; min: 0 for absolute bars) and diverge around a zero baseline for signed columns. Icon sets pick the rule whose at threshold is the greatest one ≤ the value. Colour scales tint the cell background across the range (a soft heat ramp; mid makes it diverging). All compose with flashing cells and add nothing to the core when unused.

const columns: ColumnDef[] = [
  { type: 'volume', key: 'marketValue', header: 'Mkt Value', dataBar: { min: 0 } },
  { type: 'number', key: 'pnl', header: 'P&L', decimals: 0,
    dataBar: {},                                  // auto-ranged, diverges around 0
    icons: [
      { at: -Infinity, icon: '▼', tone: 'down' },
      { at: 0,         icon: '▲', tone: 'up' },
    ] },
  { type: 'number', key: 'pnlPct', header: 'P&L %', decimals: 1,
    colorScale: { mid: 0 } },                      // diverging tint around 0
];

Computed columns

Set value: (row) => … to derive a column from the whole row (KPIs, ratios, deltas). The derived value flows through display, sort, filter, group/footer aggregation, conditional formatting, export and copy — like a real column. key still names the column but need not be a real field; computed columns aren't editable. In-memory mode; keep value() cheap and pure (it runs during sort/filter).

{ type: 'price', key: 'total', header: 'Total',
  value: (row) => row.qty * row.price, groupAgg: 'sum' }

Web component bo-grid/element

A framework-agnostic, fully-typed custom element for React / Vue / Angular / vanilla. Import registers <bo-grid> and injects its styles; drive the whole <Grid> API through the config property. config is safe to set after the element attaches (the React ref + useEffect pattern won't crash). See docs/frameworks.md for per-framework recipes.

The main entry also exports a GridProps type (every <Grid> prop). For rich cells from plain JS, use a column's render(ctx) hook (see Columns) — the alternative to the Svelte cell snippet.

const config: BoGridConfig = { columns, rows, height: '100%' };
document.body.append(createBoGrid(config));

Realtime bo-grid/realtime

The pipeline between a market-data socket and the grid. A feed pushes far more messages than a screen can show; writing each one straight into reactive state means thousands of updates to paint 60 frames. This coalesces raw messages per key (cheap, no reactive writes), then drains a bounded slice once per animation frame. A separate import on its own size budget — it adds nothing to the grid core (~2 KB gzip), and it is framework-agnostic: the frame scheduler is injectable.

ExportSignaturePurpose
createTickStream(opts) => TickStreamCoalescing buffer + frame-budgeted drain. push(key, patch) to ingest, start()/stop() to run, flushNow() to drain everything, pending/applied for feed health.
TickBuffernew TickBuffer(opts?)The coalescing buffer on its own (push, drain(cap), size) when you own the scheduling.
createRowIndex(rows, getRowId) => MapIndex rows by id so a patch finds its row in O(1). Rebuild when the row set changes, not per tick.
applyPatches(index, batch) => numberWrite a frame's patches onto their rows in place, skipping unchanged fields (no spurious re-render or flash).

Options: apply (required — called once per frame with at most cap entries), cap (row writes per frame, default 400), merge (how two patches for one key combine; default field-wise for plain objects), schedule (frame scheduler, default requestAnimationFrame), onError (called if apply throws — that frame's batch is lost either way, since it's already off the buffer, but the loop keeps running; default re-throws asynchronously so the error isn't silently swallowed). A batch that throws is not counted in stream.applied.

import { createTickStream, createRowIndex, applyPatches } from 'bo-grid/realtime';

const index = createRowIndex(rows, (r) => r.symbol);
const stream = createTickStream({
  apply: (batch) => applyPatches(index, batch),  // once per frame, ≤ cap entries
  cap: 400,
});
stream.start();
socket.onmessage = (e) => stream.push(JSON.parse(e.data).symbol, JSON.parse(e.data));
Per key only the latest state is applied — intermediate ticks collapse, which is what a price board wants (append a trade tape directly instead — see below). A sustained overload shows up as a climbing stream.pending rather than dropped frames. Pair it with flash: 'auto' columns and the grid flashes each changed cell in the right direction on its own.

Price ladder & time & sales

Two more pure pieces for the trading-desk surfaces — no component of their own, just the math/structure a ladder or a tape needs.

ExportSignaturePurpose
centeredWindow(totalCount, centerIndex, visibleCount) => {'{'} start, end {'}'}The [start, end) slice of visibleCount contiguous indices centred on centerIndex, clamped to bounds. Feed levels.slice(start, end) to <Grid rows> instead of scrolling — centring is array slicing, not scroll control. Even visibleCount puts the extra row on the lower-index side.
TradeTapenew TradeTape(capacity?)Capped ring buffer for a trade log — push(trade) O(1) regardless of session length, toArray() a fresh snapshot newest-first (call once per render), size/capacity, clear(). Default capacity 500. Unlike a price update, a trade is never coalesced — every one shows.
 
import { centeredWindow, TradeTape } from 'bo-grid/realtime';

// Ladder: 120 levels, 16 visible, centred on the spread (index 60)
const { start, end } = centeredWindow(120, 60, 16);
const visible = levels.slice(start, end);

// Tape: capped, newest trade first
const tape = new TradeTape(500);
socket.onmessage = (e) => tape.push(JSON.parse(e.data));
rows = tape.toArray();
"Scroll-lock" (follow the market vs. hold position because the viewer paged away) is UI state you keep yourself — a lockedCenter: number | null works well: null follows the live centre, a number freezes the window there until the viewer re-locks. See the Price ladder and Time & sales demos.

Trading bo-grid/trading

Market-convention helpers for APAC trading screens. Pure functions only — no ColumnDef changes, no Grid/Cell wiring. Wire tone/formatting into a column via the cell snippet or a JS render(ctx) hook you already have. A separate import on its own budget (~1.5 KB gzip) — adds nothing to the grid core.

Price-limit tone

The APAC convention: colour by position relative to the daily ceiling/floor/reference, not just up/down — a price pinned at the limit is a different signal from an ordinary move.

ExportSignaturePurpose
resolveTone(value, bands, opts?) => ToneClassify a value against {'{'} ref, ceiling?, floor? {'}'} → 'ceiling' | 'floor' | 'ref' | 'up' | 'down'. ceiling/floor are optional — omit for plain up/down/ref. opts.epsilon absorbs float noise at a boundary (default 1e-6).
toneColor(tone, colors?) => stringTone → CSS colour: purple ceiling, cyan floor, yellow ref, green up, red down. Uses darkToneColors by default; pass lightToneColors on a light theme, or a partial object for your own tones. Both palettes keep every tone at WCAG AA (4.5:1) on the grid's presets for their side.

Vietnam bands (HOSE/HNX/UPCOM)

Standard non-special-session rules only — no IPO first-day band, no ex-dividend reference adjustment. A broker with exact business rules should compute bands server-side and hand {'{'} ref, ceiling, floor {'}'} straight to resolveTone.

ExportSignaturePurpose
vnTickSize(price, exchange?) => numberMinimum price increment at this price. HOSE steps 10 → 50 → 100 VND by price band; HNX/UPCOM flat 100 VND. Default HOSE.
vnBandPercent(exchange) => numberDaily band width: HOSE 7%, HNX 10%, UPCOM 15%.
vnBands(ref, exchange?) => ToneBandsCeiling/floor from a reference price — ceiling rounded down to a tick, floor rounded up, so neither exceeds the true regulatory limit.
vnFuturesBands(ref) => ToneBandsVN30 index futures: ±7% of the reference (VN_FUTURES_BAND) on a 0.1-point step (VN_FUTURES_TICK), ceiling rounded down and floor up.
roundToTick(price, tick, mode?) => number'down' | 'up' | 'nearest' (default). Works in tick units to avoid float drift on a fractional tick (an FX pip).

Session state

ExportSignaturePurpose
sessionStateAt(date, schedule, opts?) => SessionState'pre-open' | 'ato' | 'continuous' | 'break' | 'atc' | 'closed'. Evaluated via Intl in opts.timeZone (default Asia/Ho_Chi_Minh) — correct for a viewer in any time zone. opts.skipWeekends (default true) reports 'closed' on Sat/Sun.
VN_HOSE_SCHEDULESessionWindow[]HOSE's standard weekday schedule: ATO 09:00–09:15, continuous 09:15–11:30, break 11:30–13:00, continuous 13:00–14:30, ATC 14:30–14:45. Doesn't account for holidays or special sessions.

import { vnBands, resolveTone, toneColor, fmtTradingPrice, vnTickSize } from 'bo-grid/trading';

const bands = vnBands(row.ref, 'HOSE');         // { ref, ceiling, floor } — tick-rounded
const tone  = resolveTone(row.price, bands);   // 'ceiling' | 'floor' | 'ref' | 'up' | 'down'
const color = toneColor(tone);                 // CSS colour for that tone
const text  = fmtTradingPrice(row.price, vnTickSize(row.price, 'HOSE')); // "68,500"
None of this needs Grid/Cell support — wire it into a type: 'custom' column's cell snippet (or a JS render(ctx) hook) exactly like any other custom cell. See the VN board demo, which composes it with bo-grid/realtime.

Grouping

Pass groupBy (column keys) for single or nested grouping. Groups are collapsible, headers stick to the top while scrolling, and any column with a groupAgg shows a live subtotal. Group headers are the same height as rows, so virtual scrolling stays smooth.

Server-side data

Back the grid with a RowSource to load only the visible window — the dataset can be far larger than memory. Sort and filter are delegated to the source; unloaded rows render as skeletons. (Grouping is client-only.)

RowSource interface

interface RowSource {
  getRows(p: {
    range: { start: number; end: number };  // half-open window
    sort: SortState | null;       // primary key (= sorts[0])
    sorts?: SortState[];           // full multi-column order
    filter: string;
  }): RowSourceResult | Promise<RowSourceResult>;
}
interface RowSourceResult { rows: GridRow[]; total: number; }
const source: RowSource = {
  async getRows({ range, sort, filter }) {
    const r = await fetch(`/api/rows?offset=${range.start}&limit=${range.end - range.start}`);
    return r.json(); // { rows, total }
  },
};
<Grid {columns} {source} height={640} />

Theming

Dark-first and self-contained — no CSS import required. Override any token by setting the matching --bo-grid-* custom property on an ancestor, or pass the theme prop a custom token map.
